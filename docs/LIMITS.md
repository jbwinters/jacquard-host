# Limits

These are claim boundaries for the first host integration, not background
aspirations. Evidence may remove a limit only through a reviewed change that
also updates this document.

| Initial limit | Consequence | Evidence required to remove it |
|---|---|---|
| First-party Jacquard programs only | Capability checks do not make hostile uploaded code safe. | A separate-process or equivalent isolation design, adversarial review, resource ceilings, and a narrower public threat model. |
| Trusted host and operating system | A malicious or buggy adapter can misreport or perform actions outside Jacquard. | An authenticated, independently enforced host boundary and external security review; canonical hashes alone are insufficient. |
| Application capability boundary, not OS sandbox | Declared and checked effects are review and application enforcement, not kernel isolation. | An explicit OS/WebAssembly/container isolation layer with its own evidence and deployment contract. |
| Experimental process carrier (Core's `v0`, evidence pack published) | Message framing may change and is not a permanent ABI promise; Python, TypeScript, Go, and Rust replay the pinned kit independently, while a stable protocol decision remains Core's. | Two independent adapters and the serial application pass the same frozen fixtures before Core declares protocol v1 stable. |
| Handlers run inside the adapter's read loop | A Python operation handler that blocks holds the worker until it returns. The host deadline is one lifetime budget from spawn, enforced on pipe reads, writes, and exit waits; a slow handler spends the budget and the next carrier operation expires. It cannot interrupt Python handler code. | A handler timeout policy with its own cancel/unknown-completion evidence, once an application needs one. |
| Go worker descendants that leave the process group | The Go host stops the worker's process group at expiry, and on Linux also after exit while a descendant still holds stderr; elsewhere, and for a descendant that called `setsid` (or otherwise left the group), it only stops reading the pipe. | An OS-level containment mechanism (for example a cgroup or job object) with its own evidence. |
| Go handler cancellation is cooperative | At the deadline or on context cancellation the Go host kills the worker's process group (while the worker is unreaped, which Linux guarantees), closes its pipes, and reaps it, cancels the handler's context, and sends no late response; a handler that ignores its context keeps running in its goroutine until it returns. No outside action is stopped or rolled back. | A separately enforced operation lifetime with explicit completion and reconciliation evidence. |
| Rust worker descendants that leave the process group | The Rust host stops the worker's process group at expiry. On Linux it also stops the group after exit while a descendant still holds stderr, because `waitid(WNOWAIT)` keeps the leader unreaped. Elsewhere, and for a descendant that left the group, it stops waiting once the grace or the lifetime deadline ends. On Unix its pipe threads then stop within one poll interval and the pipes are closed, but the descendant keeps running. Non-Unix targets only type-check: their pipe I/O cannot be interrupted, so disposal can hang while a descendant holds a pipe, and the offline stand-in, and so the offline suite, is Unix-only. | An OS-level containment mechanism (for example a cgroup or job object) with its own evidence. |
| Rust handler cancellation is cooperative | Each Rust handler runs on its own thread. At the deadline or on cancellation the host kills the worker's process group, closes its pipes, reaps it, and sends no late response; `HandlerContext::is_cancelled` turns true, and stays true once the invocation ends. A handler that ignores it keeps running on its thread until it returns. No outside action is stopped or rolled back. | A separately enforced operation lifetime with explicit completion and reconciliation evidence. |
| Rust adapter is protocol-level only | Rust callers pass exact identities, boundary types, and protocol values to a prepared store; there is no Rust SDK for program preparation, native type mapping, or caching. | A Rust SDK with typed-binding and preparation evidence comparable to the other SDKs. |
| Node handler cancellation is cooperative | The Node adapter can expire while awaiting a Promise, signal the handler, and kill the worker; it cannot stop an outside action or preempt JavaScript that blocks the event loop. No late response or automatic retry follows expiration. | A separately enforced operation lifetime with explicit completion and reconciliation evidence. |
| Socket host closes without a response on its own failures | A ceiling violation, early disconnect, or failed invocation ends the connection silently; clients see a reset, not an HTTP error. | An owner decision that the host may emit fixed minimal status lines, recorded here with the exact bytes and the rule that they carry no application meaning. |
| Request bytes cross as Latin-1 `Text` | v0 has no bytes value; each byte is one codepoint 0..255 and a response codepoint above 255 is refused by the host. | A frozen bytes value in a later protocol version. |
| Host frames requests by `Content-Length` only, leniently | `Transfer-Encoding` bodies are not framed and the head alone is relayed; on a repeated `Content-Length` the first wins and leading zeros are read as their value. The Jacquard parser rejects every such shape, so a leniently framed request never reaches a handler, but unread body bytes may make the close a reset that costs the client the Jacquard-authored error response. | An application need for chunked bodies and a reviewed framing rule shared by host and parser. |
| Narrow HTTP/1.1 subset | Only GET and POST with an explicit Content-Length body are served; chunked bodies, keep-alive, pipelining, HTTP/2, and TLS are rejected or absent. | A concrete application need with its own fixtures and a reviewed widening of `src/jacquard_host/data/jacquard/http.jac`. |
| Serial execution | One request is processed at a time; no throughput or concurrency claim exists. | Measured need, a reviewed Core C4 contract, cancellation/leak evidence, schedule provenance, and strict replay boundaries. |
| Loopback listener by default | The integration is not a public network service. | Explicit non-loopback configuration and authority, deployment hardening, external review, and supported operational evidence. |
| No TLS, authentication, proxy semantics, or abuse prevention | Those are ordinary deployment responsibilities outside Jacquard Host. | They remain outside this repository unless a concrete generic host requirement is separately approved; no vendor-specific coupling is implied. |
| No outbound network in the first application | The synthetic trial cannot call APIs, analytics, or email services. | A concrete application need and reviewed host/port authority with refusal evidence. |
| Host-owned SQLite through one named operation | Jacquard receives neither raw SQL nor generic filesystem authority; `study.save-response` is given a synthetic session token by application contract (the host cannot verify what a token denotes), and its receipt is a content hash with no timestamp. | Repeated concrete operations justify a reusable storage contract with migration, recovery, and authority evidence. |
| No automatic side-effect retry | An ambiguous completion fails rather than risking duplicate external work. | Operation-specific idempotency keys, authenticated receipts, and crash/recovery evidence. |
| SDK uses explicit application data mappings | The pinned CLI does not export structured constructor layouts. Python dataclasses, TypeScript record codecs, and Go records must follow Jacquard positional field order; ambiguous names across declaration groups are refused. Core validates wire types. | Core's versioned host-format interface exporter and independent typed-binding conformance. |
| Go fulfillment is a single-process snapshot example | Atomic JSON replacement demonstrates booking/outbox recovery and deduplication, without cross-process locking or power-loss durability evidence. | A concrete production storage contract and crash/concurrent-writer evidence. |
| JavaScript numbers have a smaller exact integer range | Native safe integers and the TypeScript `int` codec use numbers; full 63-bit Int values require bigint (or the explicit bigint codec). Unsafe numeric input is refused. | An explicit application choice of bigint; no silent precision loss is allowed. |
| TypeScript fulfillment is a single-process snapshot example | Atomic JSON replacement demonstrates booking/outbox recovery and deduplication, without cross-process locking or power-loss durability evidence. It is not the Python SQLite implementation. | A concrete production storage contract and crash/concurrent-writer evidence. |
| SDK checks all operations in each declared root effect | Missing bindings are refused before an SDK invocation; operations a particular path may never reach are still required. The low-level adapter retains dynamic E1606 refusal when an operation is reached. | A checked Core export of exact operation requirements with its own completeness contract. |
| Linked lists consume JSON nesting | Under default v0 ceilings the experiment's List Int fits 30 elements and rich incident output fits 28. SDK input checks and explicit pure batching improve handling, but do not guarantee derived outputs fit. | A reviewed Core bulk-value contract, or a concrete bounded input/output shape with its own evidence. |
| Exact replay uses controlled sanitized fixtures | Production traffic is not silently archived for replay. | A reviewed data classification, consent/retention policy, redaction proof, and secure evidence store. |
| Linux deployment first; macOS development support | Windows and other hosts have no support claim. | CI, lifecycle, path/socket, packaging, and cleanup evidence on each added platform. |
| Synthetic readability slice only | No participant result or readability claim may be produced here. | A separate study repository with approved protocol, consent, privacy, retention, accessibility, and publication authority. |

The integration also inherits every applicable limitation of its pinned
Jacquard Core release, including coarse 0.2 world grants and the absence of a
production-security claim.
